# 看板性能验证 · 2026-11-10

## 线上结果

同一台浏览器、Web 端默认日趋势范围，时间从 navigation start 到首张实际金额卡片出现的 DOM 标记。不是全网 SLA，也不是所有卡片完成绘制的时刻。

| 条件 | 指标出现时间 |
| --- | ---: |
| 第一版优化，新版 JS 首次下载 | 4795ms |
| 最终版本，新版 JS 首次下载、CSS 已缓存、接口已缓存 | 2674ms |
| 最终版本，静态资源和接口缓存，复测 1 | 546ms |
| 最终版本，静态资源和接口缓存，复测 2 | 429ms |
| 最终版本，静态资源和接口缓存，复测 3 | 517ms |

最终首次下载样本中的 JS 下载耗时 1971ms。最终热缓存样本中的卡片 API 约 186–264ms；首页构成汇总约 197–216ms；完整趋势约 197–281ms。三个样本不能用于声明 P95。

## 已发布

- 支付结果专用部分索引；在 SQL 侧先聚合，保持 all/web/app、设备、支付分类与历史语义。
- 三张卡片独立轻量接口，不等待链路或续订诊断查询。
- 首页只请求支付构成汇总，不运行完整模型/功能下钻；原完整接口保留。
- 压缩大响应缓存，后台持久化，已确认线上缓存记录以 gzip 格式成功落库。
- 其他分析工作区按需加载，移除首页预取和旧请求 SDK；主包 gzip 从约 887KB 降到约 565KB。
- 右栏各来源分别更新；报告最新记录优先读 D1；相同在途读取合并；轮询完成后再安排下一次，防止慢请求堆积。

## 验证与边界

类型检查通过；压缩缓存、支付结果汇总、轻量/完整构成一致性、单份多端事实、动作读取、单日回刷等共 9 个测试通过。已有本地真实快照对比覆盖三个端口和三种时间粒度，金额语义一致。

指定日期回刷已改为单日期组件，发送 startDate=endDate。生产验证时存在真实同步任务，未执行或打断回刷；日期选择与边界在本地验证。

首次访问仍未达到 1 秒。若把首次访问也纳入目标，需要继续压缩首页必需 JS，并考虑由服务端直接输出经过权限与端口校验的指标快照，让真实金额不依赖主包下载完成；快照需携带更新时间，数据同步完成后按版本更新，并在目标网络上持续记录首个数据可见时间的 P75/P95。
