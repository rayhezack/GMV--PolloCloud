# 支付与创作诊断：按核心因子选择证据

## 收入结果先行

先写包含 API 的总日均 GMV 变化，再区分主动付费、自动续订、API 三个独立收入项；主动付费相关时，明确首订、积分包、升级、重新订阅中谁是主要驱动，兼顾对冲项。API 不进入主动付费漏斗归因。

随后先按注册新老拆主动付费链路 GMV，再对新老用户各自的主漏斗使用已计算的加法 LMDI，定位各自核心、次要过程因子。新用户指对应业务周注册、老用户指该周之前注册；未知注册信息单列，不混入新老。创作分层是后续可选下钻。金额效应是核算解释，不是因果估计。现有证据若仅覆盖某创作分层，明确缺少注册新老分析，结论限定于实际证据范围。没有付费类型与过程指标的交叉证据，不能写成“积分包下降由某分层的支付率下降造成”。

自动续订必须先拆产品类型：从支付结果的 Ultra／Pro／Lite（其他、未知保留）日均续订GMV变化及其对自动续订净变化的贡献，定位同向贡献最大的核心类型。随后进入该类型的独立续订链路，以“该类型到期人数 × 该类型续订率 × 该类型续订客单价”做LMDI，定位该类型内部核心、次要因素和对冲，再核对适用于该类型和到期队列的产品动作。不能跳过产品类型直接拆整体续订。

报告章节对应：第一章展示结果类型贡献和核心类型选择；第二章同时呈现主动付费与核心类型自动续订的链路结论和证据表。注册新老需有漏斗人数与五因子金额归因；核心续订类型需有自身链路GMV、到期和续订人数、三因子金额归因。不能把续订因子只放第一章，导致支付链路章节只有主动付费。

用户2026-11-09已确认：续订链路档位是到期时的原订阅档位，Ultra／Pro／Lite可与支付结果按同名类型对应分析；不代表续订目标档位或相同订单。其他类型不自行映射。

类型贡献分母是支付结果的自动续订GMV净变化；三因子贡献分母是所选类型的续订链路GMV变化。不能把独立来源的链路效应换算成支付结果收入影响，也不要求两来源对账。缺少类型数据或未验证产品类型与plan_tier的对应关系时，明确待补证据，不假装已完成。后续统一数据源另行处理。

只对各组已选定的核心、次要因子准备下钻证据，无论改善或下降。其他因子保留数值和必要对冲，不展开下钻；国家、渠道结构不是每次诊断的必查项。

进入分支后再次收敛：按该层贡献只呈现主要分组与必要对冲，不穷举所有分类。全量数据可供模型核对，不等于正文逐项汇报；正文以关键结论、最少必要证据、具体核查为终点。没有业务结论需要的维度不增加结构拆解。

## DAU：先定位规模，再论证国家结构与获客来源

1. 按国家层级拆日均 DAU 增减、对净变化的贡献和活跃人数占比。区分“各组人数减少”和“不同组占比变化”。是否展开国家或渠道证据，先服从已选定的核心、次要因子；不因其他因子单独下滑而自动新增下钻。总 DAU 不变或增加时仍可能有结构变化，但不能因此在每次诊断中强制检查结构。结构影响已包含在总体转化率或客单价中，不额外叠加一笔 GMV 影响。
2. 只有该层级实际目标比率、每活跃用户 GMV 等数据支持，才能说某层级的对应指标较低。不能因为标签是 T3 就断定付费意愿低、流量质量差；支付完成率也不能直接测量付费意愿。
3. 发现国家层面的结构线索后，继续查投放：哪些国家点击量增加或减少、对点击净变化贡献多少、点击占比如何变化。按已经确认且适用于比较期的国家映射聚合到同一层级，核对日期、端和国家定义。不能用经验补映射，也不能拿注册国家与访问国家直接视为同一字段。
4. 点击证据之后，继续核对同国同端的曝光、花费、CTR、CPC、注册人数、点击到注册的比率；它们分别帮助区分预算规模、广告触达、点击表现和获客承接。点击与注册的人群/归属日期不能对齐时，只并列描述，不能当作严格漏斗转化。
5. 补充活跃用户中新老构成、自然与付费来源、回访活跃、成熟获客 cohort 留存，以及点击到到站/注册/活跃的用户关联。当前未提供的字段只列为人工核查所需证据，不能声称已经分析。链路的周注册新老、创作的当日注册新老不直接互换。
6. 点击不是去重用户，也不等于 DAU。两者同向只支持“投放侧变化与流量结构变化方向一致”，不能计算点击解释了多少 DAU，不能据此确认投放是根因。不同来源链路尚未桥接时，明确留待人工核实；报告不编造自然流或回访流减少。

## 付费墙曝光率：类型/原因、积分消耗与策略分支

1. 先写总体付费墙曝光率变化和曝光人数变化。曝光率也会受 DAU 分母影响，不能仅凭曝光人数下降解释曝光率下降。
2. 分别按曝光类型、曝光原因做人数增减分解；先核对分类与整体曝光 UV 守恒，多类型、未知单列。两套视角有重叠，不能把它们的影响相加。类型与原因没有未曝光 DAU，不做这两类维度的曝光率结构/效率归因。
   完整分类用于后台核对守恒；报告只写贡献最大的类型/原因，以及不保留就会误读净变化的对冲。两张边际表不能拼成交叉人群，例如不得把“按类型是被动曝光、按原因是产品设计类”缩写成“产品设计类被动曝光”。不逐条列所有权益、积分、未知分类的增减。
3. 若“积分不足”是核心变化，说明被积分门槛拦截的曝光人数变动，再检查整体/功能任务量、每活跃用户任务数、成功与采纳等行为证据。任务数不能直接证明积分消耗：还需人工核查功能单位积分、赠送积分、积分余额与积分消耗记录；缺少用户关联时，不能说创作增加的就是被拦截的同一批人。
4. 若提供的动作、时序与影响范围支持某项策略改变曝光，优先报告该策略候选及证据，不强制追加创作解释。仅有动作名称或同期变化仍不等于已确认策略影响，需人工核对生效配置、覆盖人群及曝光日志。

## 付费墙提交率：产品动作优先

该指标是提交支付 UV / 曝光 UV，旧展示名可能为“支付提交率”。暂无已确认的独立下钻维度时，不自行添加细分。查产品动作明细中的定价、默认展示产品、权益、套餐展示等，逐项检查时间、路径、端和方向。无匹配记录时写“尚无支持该解释的产品动作记录，需人工核查付费墙配置及发布记录”，不自行判断涨价、权益减弱或购买意愿下降。

## 提交支付率：先结构，再效率，国家与提交渠道并行

1. 使用已计算的 Shapley 双因素分解，写清总体 pp 变化、结构效应和组内效率效应。说明主导项及另一项是拖累还是对冲。
2. 分别从国家层级与提交时选择的支付渠道解释结构：引用对应的提交人数占比和实际组内提交支付率。成功支付渠道不具备完整提交分母，不用于替代提交渠道。未知、多渠道以及不可比组按计算结果保留，不补零或删除。
3. 两套分解解释同一总体变化，不能相加，也不能从两个边际分解推断“某渠道在 T3 支付率下降”；这类结论需要国家层级 × 提交渠道的交叉数据。渠道内效率变化仍可能含渠道内部国家构成变化，不能直接等同技术支付能力变化。
4. 结构论证后，再论证组内效率；必须查找提供的产品动作明细中与渠道、支付流程、路由、认证等相关的动作。找不到匹配动作时，保留效率变化事实，明确动作证据缺失，并列出人工需要核查的发布、配置或日志。不得自行假设故障、风控变化或渠道策略变化。
5. 按 `ratio-drilldown.md` 和真实周案例写作。第二章用紧凑表提供支持判断的结构／效率／未归因总影响与贡献，再给主要分组和必要对冲的提交占比、组内率及相关pp影响；不强制国家与渠道的每个分类都展示原子数与全效应。表前判断、表内关键证据，不在长段落逐行复述。效率与结构对冲不自动构成辛普森悖论；没有反转信号时不反复说明“不属于辛普森悖论”，不使用无证据的“根本原因”“效率崩塌”。

## 客单价：查产品动作，不从结果反推策略

查定价、折扣、套餐、权益与默认产品等匹配动作，核对生效时间、端、适用人群及方向。有已提供的套餐构成数据时，可以陈述构成变化，但不能据此反推某项产品动作发生。没有匹配动作时，保留客单价变化事实，交由人工核对配置与订单明细，不自行提出提价或套餐调整。

## 创作链路：交付、使用与持续行为

业务分析路径是“发起创作 → 有效任务 → 生成成功 → 结果采纳 → 再次创作 → 后续付费/续订”。这不是现有数据天然完整覆盖的同人群漏斗。只使用提供的环节、分子分母和业务定义，不能补发起埋点或拼接不同用户/任务/产出单位。

- 生成交付：在请求/任务规模的背景下判断成功指标，再定位功能。不能用任务增多直接证明交付改善。
- 结果使用：成功指标稳定而采纳指标下降，说明结果使用行为需要核查，不直接认定内容质量、需求或吸引力下降。采纳按任务或产出计算须使用对应分母，不能混用。
- 持续价值：比较同样成熟窗口的 D3/D7/D30 创作留存；NULL 不当作零。没有相同 cohort 的后续付费/续订关联时，不能给出创作留存导致收入变化的结论。
- 功能任务量可以在守恒后加总；功能用户会交叉，总体去重用户使用总表。未归因功能用于对账，不能当成具体产品功能解释。

## 核查建议与五分钟阅读

顶部提炼对业务解释的判断与优先待查问题；正文保留五章完整论证，核心与次要因子均有对应数字、比较和证据边界。五分钟阅读靠层次和重点，不靠删去论证。建议必须落到已读的具体动作或已定位的业务问题，说明比较哪些人群、国家、渠道、功能或套餐、看什么指标，以及结果能区分什么业务解释。仅写“查日志/配置/发布记录，确认是否变化”不构成建议；证据不足时不凑条数。参照 `historical-report-style.md`。未确定原因时不提出实验、预算、定价、渠道切换或回滚动作，不虚构责任人、时限和收益。


## 产品动作窗口：四周检索、两周优先、按机制追溯

- 默认检索分析周及此前三周，优先匹配分析周与上一周。本次分析周为 2026-10-31–2026-11-06，检索窗口为 2026-10-10–2026-11-06，优先窗口为 2026-10-24–2026-11-06。
- 曝光、提交、完成支付及客单价先看当期直接影响；创作按实际使用时间匹配；D7/D30 按被观察 cohort 的动作接触时间追溯；续订区分当期支付配置变化与用户订阅/使用历史。
- 较早上线但近期扩大覆盖的动作，使用已经提供的扩大覆盖记录匹配，不能凭空假设灰度。动作发生在两期之前且两期覆盖不变时，其存在本身不足以解释周环比变化。
- 核对时间、路径、范围、方向四项；相关动作仅作为解释线索，不强行给因果。找不到则明确已定位的指标与人群、已检查的范围和待人工检查的配置或发布记录。
- 若本次只提供两周动作或未提供动作，明确四周覆盖尚不完整，不声称已查全。不能拿实验通常持续几周，直接证明诊断动作窗口应取几周。

参考依据：Google 要求将版本、开关及动态配置变化与指标关联，并警惕虚假相关；微软指出效果可能随用户适应及其他时间因素变化。四周/两周是本项目已对齐的检索规则，不是上述来源声称的行业统一规则。
