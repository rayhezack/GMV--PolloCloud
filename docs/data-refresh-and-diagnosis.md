# 数据刷新与诊断调度

所有时间均为北京时间（Asia/Shanghai）。

## 数据何时更新

每天 **09:20** 创建当天唯一的持久化刷新批次，目标统计日为昨天。依次同步产品动作、支付结果、支付链路、自动续订、创作积极性，再更新广告和创作链路的指定历史窗口。

每 **5 分钟** 的调度只推进既有批次和报告队列，不创建新的每日批次。同一批次、数据集、日期绑定同一同步任务；成功后继续下一步，失败停止并保留原因，不能在下一次调度重新创建相同拉数任务。浏览器轮询只观察定时任务，不能执行或重建它。管理员显式恢复/重试除外。

广告的每日刷新窗口：最近 7 天及距目标日 14、30、60、90、180 天的 cohort，用于回收逐步成熟的收入。创作链路窗口：最近 4 天及距目标日 7、30 天，用于回收延迟创作结果。它们不是每五分钟重刷全部历史：每个目标日期每天最多成功自动刷新一次；频率锁限制失败后至少一小时才能再尝试，但当前批次遇错即停，需管理员显式恢复，不承诺自动每小时重跑。

## 为何出现大盘、Web、App

这些是口径范围，不能相加：大盘已包含子端。支付结果只查询一次全端 ADS，Web/App 从设备字段筛选；支付链路的全端查询也已返回分端结果。创作积极性与续订保留独立聚合口径，分别查询各端，写入对应数据集/端/日期，覆盖对应旧记录，不追加重复累加。创作链路和广告的 ADS 查询一次覆盖所有端。

## 指定日期回刷

在「数据与口径 → 同步模式 → 指定日期回刷」选择单日和数据集：付费类型、支付链路、创作积极性、自动续订、创作链路或付费广告。也可选择全部基础数据（前四项）。

只更新所选数据集和日期；查询、校验失败保留原数据。沿用「查看任务」、步骤进度、暂停和继续。暂停在当前步骤完成后生效；不强制中断已经提交到仓库的 SQL。已有活动任务时不会把新的范围静默替换成旧任务。点击「各数据集更新日期」可查看六类来源各自最新入仓日期；“基础数据已更新”仅指前四类，不代表广告/创作链路也已更新。

## 日诊断

自动监测读取 D1 支付结果；日环比和上周同日比较合并为同一指标异动。报告必须有大盘一份及各异动端各一份：仅 Web 异动生成大盘 + Web，仅 App 异动生成大盘 + App，双端异动生成三份。

支付结果、支付链路、续订及产品动作证据更新后，自动诊断至少等待 **5 分钟** 的稳定窗口，再由五分钟调度检查执行，因此实际启动会有调度等待。广告/创作链路的补刷不重置这个缓冲，也不因其失败而整体拦截已有核心证据的诊断。缺失核心证据时显示具体端、来源和日期。

**手动日诊断只读取已入仓证据，不触发任何数据同步。** 管理员可跳过自动缓冲；仍校验证据、等待活动同步结束，并遵守模型任务互斥。失败展示真实原因和进度，不把空报告或中间结果当成功。模型服务或上游不可用仍可能失败，自动恢复有次数上限，不进行无限重试。

## 周诊断

业务周为周六至周五。固定 **周六中午 12:00 Web、12:10 App** 入队（是中午，不是午夜）。周五统计日的自动日诊断由该完整业务周报告覆盖，不另行自动生成日报；既有成功日报和管理员显式手动诊断保留。

非周五统计日的异动诊断优先于定时周报，共用持久化模型执行锁。同端、同周期已有成功周诊断时复用结果。右栏底部“周诊断报告”只切换上方同一个文档组件，底部可返回日诊断。
